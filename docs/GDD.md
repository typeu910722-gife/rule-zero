# 《第零條規則》Rule Zero — 遊戲設計文件（GDD v0.1）

> 一句話介紹：在一座全是絨毛娃娃居民的粉彩小鎮裡，鎮上貼著十條可愛的「好孩子守則」。
> 但沒有人提過——**第零條**寫著什麼。

| 項目 | 內容 |
|---|---|
| 類型 | 劇情冒險 / 探索解謎（Cute-Horror，表面療癒、底層驚悚） |
| 視角 | 2D 俯視角（類 OMORI、UNDERTALE）＋對話立繪 |
| 平台 | PC（Steam），日後可考慮 Switch |
| 引擎 | Godot 4.x ＋ GodotSteam ＋ Dialogic 2 |
| 遊玩時數 | 第一輪 4–6 小時；全結局 8–10 小時 |
| 目標受眾 | 喜歡《心跳文學部》《OMORI》《Little Misfortune》的玩家 |
| 語言 | 繁中（主）、英文、日文、簡中 |

---

## 1. 設計支柱（Design Pillars）

1. **可愛是包裝紙，不是謊言** — 畫面、音樂、角色都真心可愛；恐怖來自「可愛之下的不對勁」，而不是 jump scare。
2. **規則就是玩法** — 「遵守 / 違反守則」是玩家唯一真正的選擇，也是推動劇情的核心機制。
3. **細節會說話** — 真相從不被直接講出，散落在背景、對話的停頓、物件的改變裡。玩家「自己發現」才可怕。
4. **遊戲記得你** — 後期的驚悚會延伸到遊戲本身（存檔、標題畫面、選單），讓玩家懷疑「第零條」也適用在自己身上。

## 2. 世界觀與故事

### 2.1 表面設定（玩家一開始看到的）
主角「**小布 Pip**」是一隻剛搭火車來到 **棉花糖鎮** 的小綿羊娃娃。
鎮上住著各種絨毛動物，大家都好溫柔、好開心。廣場的公告欄上寫著《棉花糖鎮好孩子守則》：

1. 每天都要笑嘻嘻！
2. 晚上八點鐘聲響起前，要乖乖回家睡覺。
3. 不可以去鐘塔後面的森林。
4. 好朋友不可以吵架。
5. 名牌要一直戴好喔。
6. 壞掉的東西，交給熊熊鎮長修理。
7. 不要問「以前」的事。
8. 鏡子是用來整理儀容的，不要盯著看太久。
9. 新朋友來的時候，大家要一起說「歡迎回來」。
10. 守則永遠只有十條。

> 細心的玩家會注意到：第 9 條說的是「歡迎**回來**」，第 10 條則像是在防止什麼。

### 2.2 隱藏真相（絕不直接說明）
- 棉花糖鎮是一個「遺忘之處」。居民們生前或過去都是承受了巨大痛苦的人，他們的記憶被縫進絨毛身體裡、用棉花塞住。
- 守則的目的只有一個：**讓大家不要想起來**。
- 違反守則、開始想起過去的居民會被「交給熊熊鎮長修理」——回來時外表一樣，但性格被「重新塞過棉花」，而且其他人都不記得原本的他。
- 小布不是第一次來。他的火車票上蓋滿了幾十個日期戳章；每當他快要想起來，世界就會從「第一天」重新開始。
- 鐘塔頂端藏著真正的第一條——**第零條規則**：

> **「第零條：不要想起來。」**

### 2.3 真相的「重量」
小布真正的過去刻意保持模糊（暗示：失去重要的人、與罪惡感有關），讓玩家將自己的情緒投射進去。結局主題是：**遺忘帶來的幸福，與記住帶來的痛苦，哪一個才是真正的自己？**

## 3. 角色

| 角色 | 外表 | 表面個性 | 隱藏真相 |
|---|---|---|---|
| **小布 Pip**（主角） | 小綿羊，名牌寫著「Pip」 | 安靜、好奇 | 輪迴了很多次的「新朋友」；名牌下其實縫著另一個名字 |
| **熊熊鎮長 Mayor Bubu** | 巨大的泰迪熊，永遠在笑 | 慈祥、愛發糖果 | 鎮的守護者兼「修理者」。不是反派——他真心相信遺忘是慈悲 |

## 4. 核心玩法

### 4.1 核心循環（每一天）
```
早上起床 → 看公告欄（守則可能有變化）
   → 自由探索小鎮：聊天、幫忙、小遊戲、收集
   → 抉擇點：遵守 or 違反某條守則
   → 晚上 8 點鐘聲 → 回家睡覺（或不回家…）
   → 夢境片段（依當天行為解鎖）
```

### 4.2 守則系統（Rule System）— 主要機制
- 每條守則都是一個**可被違反的開關**。違反會：
  - 解鎖「記憶碎片」（推進真相）
  - 提高隱藏數值 **「線頭值 Loose Thread」**
- 線頭值越高，世界的「不對勁」越明顯（見 4.4 異常系統）。
- 線頭值過高且被鎮長發現 → **「修理」**：時間回到第一天（但部分痕跡保留）。

| 守則 | 違反方式範例 | 獎勵 / 後果 |
|---|---|---|
| 2. 八點前回家 | 晚上偷溜出門 | 看見夜晚的鎮：居民們面無表情地站在原地 |
| 3. 不去森林 | 走進森林 | 找到被丟棄的「舊零件」——舊版本居民的身體 |
| 5. 戴好名牌 | 拆下名牌 | 名牌背面縫著另一個名字；NPC 對你的稱呼改變 |
| 8. 不看鏡子 | 盯著鏡子 10 秒 | 鏡中孩子出現，給出線索 |

### 4.3 記憶碎片（Memory Fragments）
- 共 12 片，以「縫在物件裡的布塊」呈現。
- 每片解鎖一段短夢境（畫風從粉彩逐漸轉為褪色、寫實的線稿）。
- 集滿特定碎片 → 解鎖鐘塔、真結局路線。

### 4.4 異常系統（Anomaly System）— 不明顯驚悚的關鍵
依線頭值分 4 階段，**所有異常都很小、不解釋、可能被錯過**：

| 階段 | 範例 |
|---|---|
| 0 純真 | 一切正常 |
| 1 違和 | 背景居民偶爾眨眼不同步；BGM 某個音符走音；公告欄數字字型略不同 |
| 2 裂縫 | 被修理過的居民身上出現新縫線；對話框文字閃一下錯字；Lulu 叫錯名字 |
| 3 綻開 | 守則變成 11 條但第 10 條仍寫「守則永遠只有十條」；遠景出現站著不動的熊影 |
| 4 （隱藏） | 標題畫面改變；存檔名稱被改寫（Meta 層） |

> 設計原則：**異常永遠不配音效提示**。玩家要靠自己察覺。

### 4.5 好感度 & 小遊戲
- 每位居民有「棉花糖好感」，提升可解鎖支線。
- 可愛小遊戲：接糖果、郵件分類、捉迷藏、縫補布偶。
- 小遊戲本身也會隨線頭值變調（例：捉迷藏中多出一個「找不到的人」）。

### 4.6 Meta 驚悚層（後期）
- 存檔欄位顯示「Day 1」的存檔次數會累積（暗示輪迴）。
- 真結局前，選單「設定」會多出一個灰色選項：「記得 ／ 忘記」。
- 二周目時 Lulu 會說「你又回來了耶」。
- ⚠️ 注意：**不要真的刪除玩家存檔**，只做「看起來被改寫」的假象（Steam 評價與玩家信任考量）。

## 5. 劇情結構（7 天）

| 天 | 標題 | 主要事件 | 情緒曲線 |
|---|---|---|---|
| 1 | 歡迎回來 | 抵達小鎮、認識大家、讀守則 | 療癒 |
| 2 | 好孩子 | 幫忙居民、第一個小違和 | 療癒＋一絲怪 |
| 3 | 森林的聲音 | Fen 邀你一起違反守則 | 好奇 |
| 4 | 壞掉的東西 | Fen 被帶去修理 | 第一次不安 |
| 5 | 新的 Fen | Fen 回來了，但不一樣了；沒人覺得奇怪 | 驚悚高點① |
| 6 | 寄不出去的信 | Popo 的郵包、鏡中孩子、拼湊過去 | 悲傷 |
| 7 | 第零條 | 鐘塔、與鎮長對峙、最終抉擇 | 驚悚高點②＋釋放 |

### 5.1 結局
1. **好孩子結局**（全守則遵守）：小布快樂地住下來。最後一格畫面：他的名牌換成了新名字——下一位「新朋友」的火車正在進站。（表面 Happy End，細想最可怕）
2. **修理結局**（線頭值過高被抓）：回到 Day 1。保留部分記憶，形成輪迴。
3. **真結局：想起來**（集滿碎片＋鐘塔）：小布選擇記住。棉花從縫線中散落，畫面第一次轉為完整的寫實色彩。苦澀但溫柔。
4. **隱藏結局：留下來的人**（真結局後二周目＋救回 Fen）：與鎮長達成理解——讓居民「自己選擇」要不要記得。

## 6. 美術方向
- **主視覺**：粉彩、圓潤、毛氈 / 縫線質感，像手作布偶繪本。
- **色彩規則**：線頭值上升時，整體色彩飽和度 **極緩慢** 下降（每階段約 -5%），玩家不會意識到，只會「覺得怪怪的」。
- **縫線語言**：縫線是全作視覺母題——新縫線＝被修理過。
- **夢境**：鉛筆線稿、褪色照片質感，與小鎮形成強烈對比。
- **參考**：OMORI、Little Misfortune、Sumikko Gurashi、Coraline。

## 7. 音效與音樂
- 主題曲：音樂盒＋木琴＋鈴鐺。
- 每首曲子都有一個「壞掉版本」：同旋律但音樂盒發條變慢、走音。
- 八點鐘聲是全作最重要的音效——它應該在前期讓人安心，後期讓人恐懼。

## 8. UI / UX
- 對話框是縫在布上的標籤。
- 守則公告欄可隨時從選單查看（玩家會反覆比對，這是刻意設計）。
- 日記本：自動記錄每天事件——但被修理後，部分頁面會被「剪掉」。

## 9. 技術規劃（目標：Steam 上架）

### 9.1 為什麼選 Godot 4
- 免費、無授權費抽成，適合獨立開發。
- 2D 能力優秀，Shader 可做飽和度、縫線、雜訊等異常效果。
- **GodotSteam** 外掛支援成就、雲端存檔、統計、交易卡。
- **Dialogic 2** 提供分支對話、變數、角色立繪管理。
- （備案：純視覺小說可改用 Ren'Py，但會犧牲自由探索。）

### 9.2 建議專案結構
```
rule-zero/
├── docs/                 # 設計文件
├── game/                 # Godot 專案
│   ├── project.godot
│   ├── scenes/           # 地圖、UI、小遊戲
│   ├── scripts/
│   │   ├── autoload/     # GameState、RuleManager、AnomalyManager、SaveManager
│   │   └── ...
│   ├── dialogue/         # Dialogic 時間軸
│   ├── art/ audio/ shaders/
│   └── addons/           # godotsteam、dialogic
└── tools/                # 匯出、在地化腳本
```

### 9.3 核心系統（Autoload 單例）
- `GameState`：目前天數、時間、線頭值、旗標。
- `RuleManager`：守則定義（資料驅動，JSON / Resource）、違反判定、事件派發。
- `AnomalyManager`：依線頭值啟用 / 停用場景中的異常節點（每個異常是一個帶 `min_stage` 的節點）。
- `SaveManager`：一般存檔＋「Meta 存檔」（跨周目記錄，供 Meta 驚悚使用）。

### 9.4 Steam 相關
- 成就範例：「好孩子」、「拆下名牌」、「第一次晚歸」、「歡迎回來 ×10」、「第零條」。
- Steam 雲端存檔：需注意 Meta 存檔也要同步，否則換電腦會破壞體驗。
- 內容描述（Content Survey）：需標註「心理恐怖、暗示性的死亡 / 創傷主題」。
- 商店頁開頭**要提示**「本作含有令人不安的心理主題」（參考《心跳文學部》做法），維持驚喜同時保護玩家。
- Steam 上架流程：Steamworks 帳號 → 付 US$100 上架費 → 商店頁（至少上架前 2 週公開，建議提早數月累積願望清單）→ 參加 **Steam Next Fest** 放 Demo。
