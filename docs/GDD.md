# 《第零條規則》Rule Zero — 遊戲設計文件（GDD v0.2）

> 一句話介紹：在一座全是絨毛娃娃居民的粉彩小鎮裡，鎮上貼著十條可愛的「好孩子守則」。
> 但沒有人提過——**第零條**寫著什麼。

| 項目 | 內容 |
|---|---|
| 類型 | 劇情冒險 / 探索解謎（Cute-Horror，表面療癒、底層驚悚） |
| 視角 | 2D 俯視角（類 OMORI、UNDERTALE）＋對話立繪 |
| 平台 | PC（Steam），日後可考慮 Switch |
| 引擎 | Godot 4.x ＋ GodotSteam ＋ Dialogic 2 |
| 遊玩時數 | 每章（每一輪）約 90 分鐘，共 6 章約 9 小時；全收集約 12 小時 |
| 目標受眾 | 喜歡《心跳文學部》《OMORI》《Little Misfortune》的玩家 |
| 語言 | 繁中（主）、英文、日文、簡中 |

---

## 1. 設計支柱（Design Pillars）

1. **可愛是包裝紙，不是謊言** — 畫面、音樂、角色都真心可愛；恐怖來自「可愛之下的不對勁」，而不是 jump scare。
2. **規則就是玩法** — 「遵守 / 違反守則」是玩家唯一真正的選擇，也是推動劇情的核心機制。
3. **細節會說話** — 真相從不被直接講出，散落在背景、對話的停頓、物件的改變裡。玩家「自己發現」才可怕。
4. **遊戲記得你** — 後期的驚悚會延伸到遊戲本身（存檔、標題畫面、選單），讓玩家懷疑「第零條」也適用在自己身上。

## 2. 世界觀與故事

### 2.1 表面設定（玩家一開始看到的）
主角「**小布 Pip**」是一隻剛搭火車來到 **棉花糖鎮** 的小綿羊娃娃。
鎮上住著各種絨毛動物，大家都好溫柔、好開心。廣場的公告欄上寫著《棉花糖鎮好孩子守則》：

1. 每天都要笑嘻嘻！
2. 晚上八點鐘聲響起前，要乖乖回家睡覺。
3. 不可以去鐘塔後面的森林。
4. 好朋友不可以吵架。
5. 名牌要一直戴好喔。
6. 壞掉的東西，交給熊熊鎮長修理。
7. 不要問「以前」的事。
8. 鏡子是用來整理儀容的，不要盯著看太久。
9. 新朋友來的時候，大家要一起說「歡迎回來」。
10. 守則永遠只有十條。

> 細心的玩家會注意到：第 9 條說的是「歡迎**回來**」，第 10 條則像是在防止什麼。

### 2.2 隱藏真相（絕不直接說明）
- 棉花糖鎮是一個「遺忘之處」。居民們生前或過去都是承受了巨大痛苦的人，他們的記憶被縫進絨毛身體裡、用棉花塞住。
- 守則的目的只有一個：**讓大家不要想起來**。
- 違反守則、開始想起過去的居民會被「交給熊熊鎮長修理」——回來時外表一樣，但性格被「重新塞過棉花」，而且其他人都不記得原本的他。
- 小布不是第一次來。他的火車票上蓋滿了幾十個日期戳章；每當他快要想起來，世界就會從「第一天」重新開始。
- 鐘塔頂端藏著真正的第一條——**第零條規則**：

> **「第零條：不要想起來。」**

### 2.3 真相的「重量」
小布真正的過去刻意保持模糊（暗示：失去重要的人、與罪惡感有關），讓玩家將自己的情緒投射進去。結局主題是：**遺忘帶來的幸福，與記住帶來的痛苦，哪一個才是真正的自己？**

## 4. 遊戲結構總覽：「每輪都是新的一章」

**核心概念：輪迴＝章節。** 小布每一次被「修理」、重新搭火車抵達小鎮，就是新的一章。
玩家不是在「重玩」，而是在**記得上一輪**的狀態下進入一個**已經改變的小鎮**。

| 項目 | 設計 |
|---|---|
| 每章長度 | 約 **90 分鐘**（3 個遊戲內日 × 約 25 分鐘 ＋ 約 15 分鐘高潮與結尾） |
| 章節數 | 6 章（總長約 9 小時）＋ 解鎖條件式的終章 |
| 每章必有 | 1 個新機制、1 條新守則、1 個被回答的謎題、2 個新的謎題、1 個懸念結尾 |
| 跨章保留 | 記憶（知識）、「線頭」（能力）、選擇的後果（角色命運） |

> 參考作品：《Inscryption》的分幕結構、《Outer Wilds》的「知識就是進度」、《OMORI》的氛圍、Netflix 影集的懸念結尾。

## 5. 核心玩法

### 5.1 一天的循環（約 25 分鐘）
```
☀ 早上：看公告欄（守則可能多了一條、或某個字變了）
   → 🧸 白天：探索、聊天、幫忙、本章專屬機制
   → ⚖ 抉擇：用「膽量」違反一條守則（每天最多 1–2 次）
   → 🔔 八點鐘聲：回家睡覺，或冒險留在外面
   → 🌙 夜晚（若違規）：看見小鎮的另一面
   → 💭 夢境：解鎖一段記憶碎片
```

### 5.2 守則與膽量（貫穿全作的主機制）
- 每條守則都是可以被違反的開關。違反需要消耗**膽量**（每天回復，數量有限）→ 玩家必須**選擇**今天要揭開哪個秘密，無法一次看完。
- 違反守則會：解鎖秘密與記憶、提高**懷疑值**（鎮長的注意力）。
- 懷疑值滿 → 被「修理」→ 本章提早結束（有專屬的壞結尾，但劇情仍會進入下一章，不讓玩家卡關）。

### 5.3 線頭（跨章節的成長系統）
每章結尾，依本章揭開的秘密獲得「**線頭**」。線頭是小布從上一輪「偷偷保留下來的記憶」，可以：
- **拉線頭**：對 NPC 使用，解開他們身上的縫線，出現只有「記得的人」才有的對話選項。
- **解鎖捷徑**：例如第二章開始就知道森林的秘密通道，不用再冒險找。
- **保住某人**：在關鍵時刻花線頭，阻止某位居民被修理（影響後續章節）。

### 5.4 知識即進度
很多謎題的答案**不在本章**，而在玩家的記憶裡。例：
- 第一章在森林看到舊的小綿羊身體掛著「No.46」，Fen 說「你是第四十七個小布」→ 第四章鏡中保險箱的密碼就是 47。
- 遊戲不會提醒你。玩家想起來的那一刻，就是最好的獎勵。

### 5.5 異常系統（不明顯的驚悚）
每過一章，小鎮的「預設狀態」就壞得更深一點；章內則依懷疑值再疊加。**所有異常都不配提示音，不解釋。**

| 章節 | 小鎮的「正常」狀態 |
|---|---|
| 1 | 一切可愛，只有幾個很小的違和 |
| 2 | 「歡迎回來」的語氣怪怪的；有人換了新縫線 |
| 3 | 公告欄出現第 11 條，但第 10 條仍寫「守則永遠只有十條」 |
| 4 | 整體色彩飽和度明顯降低；音樂盒變慢 |
| 5 | 視角轉換，玩家第一次看見「修理室」 |
| 6 | 小鎮開始拆線：棉花在風中飄 |

## 6. 章節設計（每章約 90 分鐘）

| 章 | 標題 | 本章新機制 | 新守則 | 回答的謎題 → 新的謎題 | 懸念結尾 |
|---|---|---|---|---|---|
| 1 | 歡迎回來 | 守則與膽量（教學） | — | 「森林裡有什麼？」→ 舊零件是誰的？為什麼說「回來」？ | Fen 被帶走，小布也被抓到。畫面被一針一針縫起來。火車票上出現**第 2 個戳章**。 |
| 2 | 新的 Fen | 拉線頭（用上一章的記憶喚醒 NPC） | 11. 不要和以前的朋友說話 | 「被修理會怎樣？」→ 鐘塔裡有什麼？Fen 為什麼會知道？ | 被喚醒的 Fen 只來得及說：「鐘塔……第零條……」然後熊熊鎮長站在門口，笑著。 |
| 3 | 寄不出去的信 | 送信：決定每封信交給誰（讀信會讓人想起來，也會讓他被修理） | 12. 信件一律交給鎮長 | 「居民原本是誰？」→ 有一封信是寫給小布的 | 收件人寫著小布的**本名**，筆跡是小布自己的。名牌掉了下來。 |
| 4 | 鏡子的另一邊 | 雙世界切換：在鏡中世界看見居民的人類身影，解跨世界謎題 | 13. 鏡子壞了也不准修 | 「鏡中孩子是誰？」→ 小布到底忘記了什麼？ | 鏡中孩子說：「你忘記的，是我。」鏡子碎了，Lulu 出現在鏡子裡。 |
| 5 | 熊熊的夜晚 | **視角轉換：扮演熊熊鎮長**。縫補小遊戲——玩家要親手「修理」居民 | （鎮長視角看見守則的草稿） | 「鎮長是壞人嗎？」→ 他是第一位居民，守則出於慈悲 | 鎮長翻開名冊：小布的火車票有 **47 個戳章**。他第一次猶豫了。 |
| 6 | 第零條 | 改寫守則：在公告欄上劃掉、重寫規則來改變小鎮 | 0. 不要想起來 | 所有謎題收束 | 依全作選擇分歧的結局（見 6.1） |

### 6.1 結局（依跨章累積的選擇）
1. **好孩子結局**：小布選擇忘記。名牌換上新名字，下一班火車正在進站。表面 Happy End。
2. **修理結局**：懷疑值過高。回到第一章，但標題畫面多了一道縫線（可再挑戰）。
3. **想起來（真結局）**：保住 Fen、送出關鍵信件、集滿夢境碎片。棉花散落，畫面第一次轉為完整色彩。
4. **留下來的人（隱藏結局）**：真結局後，在章節選單重玩第五章並做出不同選擇，與鎮長一起把「記不記得」的選擇權還給居民。

## 7. 上癮設計：為什麼玩家停不下來

| 鉤子 | 實作方式 |
|---|---|
| **懸念結尾** | 每章最後 3 分鐘必定翻轉，結尾停在問題上而不是答案上。 |
| **下一章自動開場** | 章節結束後直接播放下一章開頭約 30 秒（火車進站、新的公告欄），**然後**才出現「存檔並離開」。類似影集自動播下一集。 |
| **問題階梯** | 每章回答 1 個大謎題、拋出 2 個新謎題。玩家心裡永遠掛著沒解開的問題。 |
| **小獎勵節奏** | 每 5–10 分鐘至少一個小發現（新對話、新異常、一段夢境），讓 90 分鐘不會有空檔。 |
| **每章新機制** | 機制從不重複，玩家會想知道「下一章要玩什麼」。 |
| **選擇有後果** | 上一章救了誰、說了什麼，下一章 NPC 都記得（或「假裝不記得」）。 |
| **標題畫面會變** | 每完成一章，標題畫面就多一個細節（多一個戳章、少一位居民）。玩家每次開遊戲都想看看這次又變了什麼。 |
| **縫線圖（流程圖）** | 章節選單是一張縫線樣式的分支圖，沒解鎖的節點顯示為「???」。補完它是全收集玩家的長期目標。 |
| **膽量限制** | 每天只能違反 1–2 條守則，一定看不完所有秘密，讓玩家想回頭重玩章節。 |

> 原則：上癮感來自**好奇心**，不是懲罰或抽卡。不做每日登入、不做付費機制。

## 8. 單章 90 分鐘節奏表（以第一章為例）

| 時間 | 內容 | 情緒 |
|---|---|---|
| 0–10 分 | 火車抵達、歡迎會、讀守則 | 可愛 |
| 10–35 分 | 第一天：認識居民、幫忙小事、接糖果小遊戲 | 療癒 |
| 35–40 分 | 第一個違和（Lulu 叫錯名字，又立刻忘記） | 小疑問 |
| 40–60 分 | 第二天：Fen 邀你晚上偷溜出門；第一次違反守則 | 刺激 |
| 60–75 分 | 夜晚的小鎮：居民面無表情地站著 | 第一次發毛 |
| 75–85 分 | 第三天：走進森林、找到舊零件、Fen 被帶走 | 驚悚高點 |
| 85–90 分 | 被抓、畫面縫合、第 2 個戳章、下一章自動開場 | 懸念 |

## 9. 美術方向
- **主視覺**：粉彩、圓潤、毛氈 / 縫線質感，像手作布偶繪本。
- **色彩規則**：線頭值上升時，整體色彩飽和度 **極緩慢** 下降（每階段約 -5%），玩家不會意識到，只會「覺得怪怪的」。
- **縫線語言**：縫線是全作視覺母題——新縫線＝被修理過。
- **夢境**：鉛筆線稿、褪色照片質感，與小鎮形成強烈對比。
- **參考**：OMORI、Little Misfortune、Sumikko Gurashi、Coraline。

## 10. 音效與音樂
- 主題曲：音樂盒＋木琴＋鈴鐺。
- 每首曲子都有一個「壞掉版本」：同旋律但音樂盒發條變慢、走音。
- 八點鐘聲是全作最重要的音效——它應該在前期讓人安心，後期讓人恐懼。

## 11. UI / UX
- 對話框是縫在布上的標籤。
- 守則公告欄可隨時從選單查看（玩家會反覆比對，這是刻意設計）。
- 日記本：自動記錄每天事件——但被修理後，部分頁面會被「剪掉」。

## 12. 技術規劃（目標：Steam 上架）

### 12.1 為什麼選 Godot 4
- 免費、無授權費抽成，適合獨立開發。
- 2D 能力優秀，Shader 可做飽和度、縫線、雜訊等異常效果。
- **GodotSteam** 外掛支援成就、雲端存檔、統計、交易卡。
- **Dialogic 2** 提供分支對話、變數、角色立繪管理。
- （備案：純視覺小說可改用 Ren'Py，但會犧牲自由探索。）

### 12.2 建議專案結構
```
rule-zero/
├── docs/                 # 設計文件
├── game/                 # Godot 專案
│   ├── project.godot
│   ├── scenes/           # 地圖、UI、小遊戲
│   ├── scripts/
│   │   ├── autoload/     # GameState、RuleManager、AnomalyManager、SaveManager
│   │   └── ...
│   ├── dialogue/         # Dialogic 時間軸
│   ├── art/ audio/ shaders/
│   └── addons/           # godotsteam、dialogic
└── tools/                # 匯出、在地化腳本
```

### 12.3 核心系統（Autoload 單例）
- `GameState`：目前天數、時間、線頭值、旗標。
- `RuleManager`：守則定義（資料驅動，JSON / Resource）、違反判定、事件派發。
- `AnomalyManager`：依線頭值啟用 / 停用場景中的異常節點（每個異常是一個帶 `min_stage` 的節點）。
- `SaveManager`：章節存檔＋「Meta 存檔」（跨章節保留的記憶、線頭、角色命運，以及標題畫面的變化）。
- `ChapterManager`：章節載入、本章機制開關、結尾懸念與下一章自動開場。

### 12.4 Steam 相關
- 成就範例：「好孩子」、「拆下名牌」、「第一次晚歸」、「歡迎回來 ×10」、「第零條」。
- Steam 雲端存檔：需注意 Meta 存檔也要同步，否則換電腦會破壞體驗。
- 內容描述（Content Survey）：需標註「心理恐怖、暗示性的死亡 / 創傷主題」。
- 商店頁開頭**要提示**「本作含有令人不安的心理主題」（參考《心跳文學部》做法），維持驚喜同時保護玩家。
- **Demo＝完整第一章**：90 分鐘、停在懸念結尾，最適合轉換成願望清單；Demo 存檔可延續到正式版。
- Steam 上架流程：Steamworks 帳號 → 付 US$100 上架費 → 商店頁（至少上架前 2 週公開，建議提早數月累積願望清單）→ 參加 **Steam Next Fest** 放 Demo。
